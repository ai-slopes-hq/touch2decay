# Нативное iOS-приложение: перенос миров в C++ по одному

Решено с автором 22.10. Зачем: нужны **AUv3, Ableton Link, фон, MIDI, многоканальный выход в USB-интерфейс** (Torso S-4 — class-compliant, 10 in / 10 out). PWA на iOS этого не даёт.

**Пересмотрено 22.10 (фаза 0б):** веб-приложение **играет в S-4 по USB-C** (раньше не шло — сейчас идёт; iPhone при этом заряжается от S-4). Автору из натива нужны **Link, MIDI и фон**; AUv3 и разводка по каналам S-4 — пока нет. Отсюда — проба нативной **оболочки** (WKWebView с вебом как есть) вместо переноса всего звука в C++; ниже — что она показала.

## Принципы

- **Веб-версия остаётся главной**, пока не перенесены все миры: на ней живёт развитие, по ней сверяется нативная. Миры заморожены (новых не делаем, имеющиеся не меняем — только баги).
- **Переносим по одному миру**, каждый — насквозь: звук, часы и модель в C++ → в приложении → в AUv3. Следующий — только когда предыдущий звучит так же, как в вебе.
- **Картинку не переписываем**: интерфейс приложения — наша же гравюра в WKWebView поверх нативного ядра.

## Схема

```
core/                       C++ (без зависимостей от iOS): одно ядро на мир + общее
  common/                   фильтры, задержки, зал (порт hall()), осцилляторы, огибающие, сглаживание, rng
  host/                     мастер (срез, компрессор, потолок knee), микшер, concordia (лад, темп), LFO строк (порт host/sl.js)
  worlds/<мир>/             состояние + часы/шаги/физика + DSP; process(out, frames); apply(сообщение); state() для картинки
  render-cli/               офлайн-рендер в WAV (для сверки с вебом, собирается на Linux/Mac)
ios/                        Swift: приложение-хост + расширение AUv3
  project.yml               XcodeGen — проект из текста, окно Xcode почти не нужно
  App/                      AVAudioEngine, AVAudioSession (фон, маршрут, каналы), CoreMIDI, LinkKit, WKWebView
  AU/                       AUv3: тот же core, свой WKWebView-интерфейс
web (как сейчас)            в нативном режиме мир не создаёт узлы Web Audio, а шлёт действия в core и рисует state()
```

**Хост тоже уходит в ядро.** Сейчас в JS не только миры, но и мастер-цепочка (`DynamicsCompressor`, потолок `knee`), микшер, `hall()`, concordia и **LFO строк** (`host/sl.js` двигает параметры из кадра ~30 Гц), а `model.tick(dt)` всех миров зовётся из `frame`. С закрытым окном AUv3 и в фоне кадров нет — LFO встанут, модели замрут. Поэтому всё, что тикает, — в ядро, JS только рисует.

**Почему модель уходит в ядро, а не остаётся в JS:** AUv3 звучит и с закрытым окном — хост (AUM, Loopy, DAW) крутит плагин сам. Значит, всё, что звучит без пальца (часы Portus, Natura, Cymatica, Horologium, физика Tria, бродяги Arcadia, кометы Firmamentum), должно жить в C++. JS остаётся **view**: касание → сообщение в ядро, ~30 раз в секунду ядро отдаёт `state()` для рисования. Так уже устроены миры с worklet (worklet = ядро, страница = картинка) — их перенос проще всего.

**Где ядро в вебе:** WASM-модуль внутри AudioWorklet; worklet-ы миров постепенно становятся тонкими обёртками над ядром.
- Сборка — **standalone wasm без рантайма** (clang `--target=wasm32` или emscripten `-sSTANDALONE_WASM`, без аллокаций в `process`). Режим emscripten `AUDIO_WORKLET` не брать: ему нужен `SharedArrayBuffer`, а значит заголовки COOP/COEP.
- Страница качает **байты** `.wasm` и шлёт в worklet `ArrayBuffer`, инстанцирует сам worklet — не полагаться на перенос скомпилированного `WebAssembly.Module` (в Safari не проверено, фаза 0).
- `.wasm` — в списки `sw.js` (офлайн) и под тот же `?v=`.

**Мост:** `window.webkit.messageHandlers.core.postMessage({w, t, …})` туда, `window.coreState(w, json)` обратно. В вебе — тот же интерфейс, только отвечает Web Audio / worklet. Шов — интерфейс мира `build / apply / snapshot / restore` + сообщения worklet.

## Решено 22.10: одно ядро и для веба (вариант б)

Ядро мира пишется один раз и собирается в двух видах: **нативно** (iOS-приложение и AUv3) и в **WASM** — его крутит AudioWorklet в веб-версии. Отказались от двух параллельных реализаций (JS в вебе + отдельный нативный код): каждую правку пришлось бы делать дважды. У веба появляется шаг сборки, `.wasm` лежит в репозитории рядом с кодом, который он заменяет; страница по-прежнему без сборщика.

**Готовое вместо велосипедов (22.10):** базовые блоки (осцилляторы VA/FM/wavetable/additive, фильтры, резонаторы, ревербы, гранулы) — из открытых библиотек с разрешительной лицензией:
- **Mutable Instruments** (`pichenettes/eurorack`, код для STM32 — **MIT**): Plaits (VA, 6-op FM, wavetable, additive, формант/речь, string, modal, шумы), Rings / Elements (модальные и струнные резонаторы), Clouds / Beads (гранулы), их ревербы и фильтры;
- **DaisySP** (Electrosmith, **MIT**): осцилляторы, фильтры, FM, Karplus-Strong, modal, эффекты; **DaisySP-LGPL не брать** — статическая линковка в App Store с LGPL плохо совместима;
- **Ableton LinkKit** (iOS) — своя лицензия: бесплатно, но с условиями (в том числе по интерфейсу Link) — прочитать и принять в фазе 0;
- блоки Mutable Instruments рассчитаны на свою частоту и размер блока (Plaits — 48 кГц, блоки по 24) — учитывать при встраивании;
- **GPL — не брать в приложение** (Surge XT, Vital, Dexed — GPL-3): с App Store несовместимо; можно смотреть идеи, не код. У библиотек Surge (`sst-*`) лицензию проверять по каждой.
- MIT требует упоминания — экран лицензий в приложении.

**Язык ядра — C++** (22.10): готовые MIT-библиотеки (Mutable Instruments, DaisySP) — на C++ и встают как есть и нативно, и через emscripten в WASM; Rust рассматривали — смесь Rust + C++ в WASM слишком хлопотна. Faust — возможно позже, для отдельных DSP-блоков.

**Свой DSP миров переносим как есть** (совпадение звука проверяется сверкой); библиотечные блоки — для нового и для общих мест, где совпадение не важно.

## Фазы (утверждено с автором 22.10)

**Порядок: живём в вебе → переписываем весь звук в C++ (в вебе — через WASM) → потом несём в Apple и пакуем.** Каждый перенесённый мир сразу звучит в вебе из ядра — проверяется на iPhone как сейчас, по Vercel.

0. **Разведка до переноса** (один раз, коротко): Goetia в C++ → WASM в вебе (проверить цикл сборки и сверку звука) и **пробная нативная сборка этого же ядра** — оболочка с WKWebView, AUv3 с Goetia, вывод в S-4 (маршрут и число каналов — почему не шёл звук из Safari), Link, фон. Цель — не делать приложение, а убедиться, что в конце не будет сюрприза (лимит памяти AUv3 с WebView, USB-аудио, подпись). Если упрёмся — менять план сейчас, а не после переноса всего звука.
   **0а — сделано в ветке `native` (22.10):** DSP Goetia — `core/worlds/goetia` (C++17), в вебе — `goetia.wasm` (12.6 КБ, standalone, без импортов) в AudioWorklet, worklet — тонкая обёртка, байты — через `processorOptions`. Совпадение с прежним JS — по сэмплам (≤ 1e-6) в 8 сценариях, включая переход t через 2³¹; нативный `render-cli` (clang, `-ffp-contract=off`) совпадает так же. Скорость (Node / V8, 60 с звука, три духа × легион 4): JS 2.3 с, WASM 0.17 с — **в ~14 раз быстрее**. Спека и план — `docs/superpowers/specs|plans/2026-10-22-native-0a-*`. На iPhone (превью ветки) автор проверил 22.10: Goetia звучит как в проде, всё на месте.
   **0б — проба оболочки (ветка `native`, `ios/shell/`, одноразовая):** SwiftUI + WKWebView с продом, `AVAudioSession .playback`, `UIBackgroundModes: audio`. Ставится без Xcode 26: `ideviceinstaller install Shell.ipa` (Xcode 16.2 не монтирует DDI на iPhone 17 / iOS 26.6, установке DDI не нужен); подпись — бесплатная (Personal Team, 7 дней). Итог на iPhone (автор, 22.10):
   - **фон работает** — и в оболочке, и **в самом Safari / PWA** (iOS 26): звук идёт при блокировке и в другом приложении, на экране блокировки — плеер (`mediaSession`);
   - **секвенсеры на JS-таймере в фоне теряют шаги** (Portus: ритм ровный, но звучат будто только первые ноты, эхо работает): таймер 25 мс в фоне будится ~раз в секунду, запас планировщика 200 мс, опоздавший шаг пропускается. То же у Natura и автострама Monochordum; у Cymatica и Horologium часы в worklet — не должны. Это баг веба, чинится в вебе (часы в worklet или больший запас, пока страница скрыта), натив не нужен;
   - значит, **натив нужен только для Link и MIDI** (UDP multicast и CoreMIDI из веба недоступны). Следующая проба — Link через мост в оболочке.
   - фон секвенсеров починен в вебе (v167, `main`): планировщики будит `T.onTick` — таймер + метроном `clock-worklet.js`; автор проверил на iPhone Portus, Natura, автострам.
   - **Link — упёрлись:** на iOS нужен entitlement Apple на multicast (`com.apple.developer.networking.multicast`) — по заявке и только платному аккаунту (Developer Program); плюс LinkKit — по запросу у Ableton. С бесплатным аккаунтом не проверить. **Решено автором (23.10): Link пока не нужен вообще** — синхронизация только MIDI.
   - **MIDI (идёт, 22.10):** шаг 1 готов — оболочка (CoreMIDI, сетевая сессия с Mac) видит часы Ableton: BPM, start / stop (плашка внизу). Шаг 2 собран, **на iPhone не проверен**: доли, start, stop → `window.t2dMidi` → `sync` в engine Portus (темп и фаза такта; пробный код, только в `native`). Грабли: страница по http с Mac — нет AudioWorklet и Wake Lock (экран гаснет, метроном не работает) → оболочка грузит https-превью `native` (нужен вход в Vercel внутри оболочки один раз); после перезапуска оболочки сетевой MIDI-сеанс на Mac надо переподключить («Настройка Audio-MIDI» → «Сеть»). Дальше: вход в Vercel → Ableton Play → Portus в такт с киком → блокировка экрана; потом — то же с S-4 по USB (если iPhone его видит: S-4 то ведомый, то хост).
   - **MIDI-ведомый работает (23.10):** Elektron Analog Rytm MKII по USB → оболочка → Portus: start / stop, темп, фаза такта — автор проверил на iPhone. Грабли: Elektron шлёт часы и на стопе (доли без start — только темп, сами не заводят); BPM по 4 долям и порог 0.3 BPM, иначе дрожь перестраивает эхо; плашку SwiftUI не обновлять на каждый тик (48/с на главном потоке — подтормаживало). Не сделано: Continue / Song Position Pointer. Дальше — **ведущий** (часы из t2d наружу).
   - **MIDI-ведущий работает (23.10):** Portus говорит оболочке шаг, темп и когда его услышат (epoch, мс, `getOutputTimestamp`) — на пуске, такте, смене темпа, стопе; оболочка (`ClockOut.swift`) сама расписывает 24 тика на долю на 100 мс вперёд с отметками CoreMIDI во все выходы. Переключатель `follow / lead` на плашке. Rytm идёт за Portus. Грабля: MIDI start без долей вешал Portus (ждал долю вечно) — пуск маяком теперь сбрасывает ожидание. Лог пробы: оболочка пишет `Documents/t2d.log` и шлёт пачки на Mac (`ios/shell/logserver.py`, пачки приходят вперемешку — сортировать по времени); в прогоне 23.10 нагрузки нет (кадр ~1 мс, звук не отстаёт, ≤2 живых удара, поток часов не опаздывает), ошибка фазы ведомого ±1 мс, редкий выброс ~20 мс от доставки доли.
   - **Analog Four вместо Rytm (23.10, автор):** и `follow`, и `lead` — идеально, в том числе при заблокированном экране. Значит, обрыв ведущего — USB-звук Rytm, не оболочка.
   - **Решено автором (23.10): t2d — ведомый, не ведущий.** «Способности Universum как хоста скромны»: доводим ведомого, ведущий (`lead`, `ClockOut`) остаётся пробой как есть. Ведомый для всех миров-секвенсеров — `docs/superpowers/specs/2026-10-23-midi-follow-design.md`. **Проверено автором на iPhone с Analog Four (23.10):** Start ведёт только миры, которые запускали руками (и мир на экране), включённый посреди игры встаёт в такт, Horologium на нуле tempus держит оборот = такт, смена деления Monochordum на ходу, темп, Stop/Start, *restart audio*, заблокированный экран — всё ок. **Собран (23.10):** `host/midi.js` — одна сетка долей на Portus, Natura, Cymatica, Monochordum (автострам) и колесо Horologium (замок на такт при tempus 0); сценарий `shot.py midi`; на iPhone с Analog Four — проверит автор.
   - **Ведущий с заблокированным экраном — надолго в бэклог (автор, 23.10).** Ведомый в блокировке держит такт, ведущий — нет: Rytm отваливается. Что видно в логе: звук iPhone идёт **в сам Rytm** (маршрут `USBAudio: Elektron Analog Rytm MKII` — Rytm по USB ещё и звуковая карта); через ~6 с после блокировки USB-устройство Rytm исчезает и появляется снова (MIDI: removed → added; звук: route `oldDeviceUnavailable` → Speaker → `newDeviceAvailable` → Rytm), AudioContext страницы — `interrupted`, звук встаёт, MIDI-порт пересоздаётся — часы уходят в пустоту. То же один раз было и без блокировки, сразу после прерывания звука. Почему в `follow` не рвалось — не ясно (возможно, повезло). Первые пробы, когда вернёмся: на Rytm USB только MIDI, без звука (тогда он не маршрут звука iPhone); или оболочка держит свой AVAudioSession (тишина), чтобы маршрут не отпускался; после `newDeviceAvailable` — заново подключаться к выходу и пускать часы с такта. Сетка ведущего теперь цепляется к такту (`Grid.swift`), после паузы звука не молчит.
   - **Итог фазы 0 (23.10, v168 — `native` влита в `main`):** автор проверил в проде Goetia на WASM и ведомого по MIDI (Cymatica — ок). Отложено: AUv3 (и вопрос о его форме ниже), MIDI Continue / Song Position Pointer — потом; ведущий — надолго в бэклог; Link — не нужен.
   В фазе 0 же **решить форму AUv3** (вопрос автору): один плагин, мир выбирается в экземпляре, — или все миры в одном плагине с выходом каждого на свою пару каналов (под S-4). От этого зависит ядро: сколько миров в одном `process` и откуда темп (хост, Link, concordia).
1. **Общая DSP-база** (`core/common`): фильтры, задержки, зал (порт `hall()`), осцилляторы, огибающие; где не важно совпадение — блоки Mutable Instruments / DaisySP (MIT).
2. **Хост в ядре** (`core/host`): мастер, микшер, concordia (лад, темп), LFO строк (`host/sl.js`) и тик моделей — до переноса миров, чтобы перенесённый мир сразу жил без кадров.
3. **Миры с worklet** — Firmamentum, Oceanus, Arcadia, Monochordum, Horologium: worklet → ядро на C++ (WASM в worklet), часы и модель — в ядро.
4. **Миры на узлах** — Inferno, Paradisus, Tria (+ GENDYN из `docs/worlds/tria.md`).
5. **Секвенсеры** — Portus, Natura, Cymatica.
6. **Tenebrae** последним.
7. **Apple:** оболочка-приложение, AUv3, MIDI (Link — не нужен, 23.10), фон, многоканальный выход, TestFlight → App Store. Интерфейс — гравюра в WKWebView (нативный — только если упрёмся в память или отклик).

Мерило для каждого мира: звук из ядра совпадает с прежним JS (рендер одного состояния, RMS ± 1 дБ, спектр по полосам), все `tools/shot.py` зелёные, **тесты моделей `tools/models/*.test.mjs` проходят против WASM-ядра** (та же спецификация, что для JS-модели — `model.js` мира заменяется обёрткой над ядром).

## Что можно делать без Mac

- `core/` и `render-cli` — обычный C++: собирается и тестируется на Linux (в облачной сессии Claude тоже), сверка с вебом — `tools/render.py` там же. Mac нужен только для `ios/` (сборка, подпись, установка на телефон, AUv3).
- Нужен аккаунт Apple Developer (платный — для AUv3 в чужих хостах и TestFlight).
