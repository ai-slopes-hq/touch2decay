# План рефакторинга: модули model / engine / view

Состояние на 22.10 (v156): не начат. `app.js` ~4 270 строк.

Зачем: возможно, придётся переписывать под iOS нативно. Тогда у каждого мира должны отдельно лежать **алгоритм** (что происходит), **звук** (как это звучит) и **картинка с касаниями** (как это выглядит и трогается). Сейчас всё перемешано в одном файле мира, а хост (`app.js`, ~4 100 строк) держит внутри ещё и весь мир I · Tenebrae.

Главное правило: **снаружи ничего не меняется**. После каждого шага все сценарии `tools/shot.py` зелёные, звук в `tools/render.py` тот же (RMS ± 1 %, время расчёта не хуже), пользователь разницы не видит.

## 3. Контракты

**Model** — то, что переписывается в Swift один в один (или живёт в JavaScriptCore):
```js
export function createModel({ scale, clock, rng }) {
  return {
    state,                      // только данные: числа, массивы, никаких узлов и canvas
    actions: { addBoat(step, p), moveBoat(b, step, p), sink(b), setFog(v), dice(), clear(), … },
    tick(dtSec),                // время: физика (Tria), бродяги (Arcadia), кометы — то, что сейчас в tick()
    events,                     // что должно прозвучать: «удар на шаге j», «нота on/off», «параметр изменился»
    snapshot(), restore(js), sounding(),
  };
}
```
- Время модели — секунды, не `performance.now()`. Случайность — через `rng` (сид), чтобы тесты были повторяемыми.
- Секвенсеры (Cymatica, Natura, Horologium, Portus) отдают **расписание**: «на шаге j — событие X» — а часы с упреждением 200 мс живут в engine (они завязаны на `ctx.currentTime`).

**Engine** — звук, переписывается в AVAudioEngine/AUv3:
```js
export function createEngine(ctx, chanIn) {
  return { start(), apply(state), on(event, t), live(on), level(), dispose() };
}
```
- `apply(state)` — выставить параметры из модели (сглаженно); `on(event, t)` — сыграть событие ко времени `t`.
- worklet-ы не трогать: они уже чистые; в iOS — C++ ядра 1:1.

**View** — картинка и касания:
```js
export function createView(T, model) {
  return { geo(), draw(now), down(f), move(f), up(f), corner, legend, fx, sheets };
}
```
- Касание → действие модели, никогда не трогает узлы звука напрямую.
- Плашки (`openSheet`) — тоже во view, `get/set` идут в модель.

## 6. Риски и как их снять

- **Safari и модули**: `AudioWorklet.addModule` с модулями и `?v=` — проверить на iOS 16/17; `document.currentScript` в модулях нет → версию брать из `import.meta.url`.
- **Сервис-воркер**: модулей станет ~60 — первая установка тяжелее; можно отдавать `SHELL` по частям (сначала хост и карта, миры — при первом входе).
- **Производительность**: дополнительные вызовы между слоями — пустяк, но `apply(state)` не должен звать `setTargetAtTime` каждый кадр без изменений (сравнивать с прошлым значением).
- **Отмена**: снимки (`snapshot`) — уже данные; при переносе следить, чтобы в модель не попали узлы и `performance.now()`.
- **Глобальное `window.t2d`** для тестов — оставить, собирать из моделей (`t2d.<мир>` → `{ model.state, actions, view.geo }`).

## 7. Нативный iOS — что куда (решать после шага 4 и проверки на iPhone)

| Слой | (а) Swift целиком | (б) WKWebView-обёртка | (в) гибрид |
|---|---|---|---|
| model | Swift (по JS как спеке) или JavaScriptCore | JS как есть | JS / Swift |
| engine | AVAudioEngine + AUv3 | Web Audio как есть, нативны аудиосессия и фон | C++ DSP (worklet-ы → ядра), веб через WASM |
| view | CoreGraphics / Metal (гравюры — те же пути) | canvas как есть | canvas |
| цена | высокая | низкая | средняя |

Рекомендация из обсуждения 21.10: сначала разделить слои (шаги 1–4), это нужно при любом варианте; выбирать (а)/(б)/(в) — после того как станет ясно, как веб-версия ведёт себя на iPhone (нагрузка, фон, блокировка экрана, Bluetooth-задержка).
