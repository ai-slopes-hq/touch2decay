# Проверка

Вынесено из `CLAUDE.md` (26.10): все тесты, сверки, сценарии и известные нестабильные места.

`python3 -m http.server 8765` в корне, затем:

- `core/build.sh` собирает всё, включая `t2d.wasm`, и в облачной сессии (emscripten из apt, см. ниже); собранный `t2d.wasm` коммитится вместе с правкой ядра. Портус: `node --test tools/test-portus-core.mjs` — wasm против нативного `portus-cli` (расхождение 0) и сцена действий фасада = снимок ядра; модель — `tools/models/portus.test.mjs` (эталон `tools/ref/portus-model.js` и фасад над ядром, случайные правки).
- `core/build.sh && node --test tools/test-goetia-core.mjs tools/test-firm-core.mjs tools/test-ocean-core.mjs tools/test-mono-core.mjs tools/test-horo-core.mjs tools/test-arcadia-core.mjs tools/test-tria-core.mjs tools/test-transport.mjs tools/test-sdk.mjs` — сверка ядер с эталоном (render-cli и `t2d.wasm`, 1e-6; MIDI-часы ядра против прежнего JS), пара минут. Шины Monochordum и Arcadia и звук Tria против прежней Web Audio — `python3 tools/mono-bus.py`, `python3 tools/arcadia-bus.py`, `python3 tools/tria-bus.py` (браузер, при запущенном сервере); `sdk::Param` против AudioParam Chromium — `python3 tools/param-check.py` (сервер не нужен). Emscripten в облачной сессии — из apt (3.1.6, `apt-get install emscripten`): свежий emsdk не скачивается; `build.sh` понимает обе версии.
- Inferno: `node --test tools/models/inferno.test.mjs` — модель против эталона `tools/ref/inferno-model.js` и ядра `t2d.wasm` (19 тестов); звук против прежнего JS на Web Audio — `python3 tools/inferno-compare.py` (браузер, при запущенном сервере; эталон — `tools/ref/inferno-engine.js`).
- Без emscripten (облачная сессия, прокси режет его скачивание): `pip install ziglang` → `python -m ziglang c++ -target wasm32-wasi … -mexec-model=reactor` собирает `t2d.wasm` для проверки (импорты WASI — заглушки); тесты берут его через `T2D_WASM=/путь/t2d.wasm`, в прод идёт только сборка `core/build.sh` (emcc). `tools/inferno-compare.py` — сверка звука Inferno с прежним JS (RMS, полосы).
- `python3 tools/shot.py <сценарий>` (solniger, vol, planets, ring, worlds, sun, hole, legenda, startmap, audio и по сценарию на мир, в том числе arcadia и portus — см. `docs/worlds/`) — сценарии касаний (CDP touch, 390×844) с проверками (провал или ошибка на странице — код выхода 1), скриншоты в `.shots/` — **смотреть их глазами** (Read на png).
- `python3 tools/natura-bus.py` — то же для Natura (прежний движок `tools/ref/natura-engine.js` + модель `tools/ref/natura-model.js` в Chromium против `core/build/natura-cli`, восемь случаев, в том числе дерево; `node --test tools/test-natura-core.mjs` — wasm = нативное).
- `python3 tools/portus-bus.py` (при `python3 -m http.server 8765`) — звук Portus: прежний движок на узлах Web Audio (`tools/ref/portus-engine.js`, Chromium, OfflineAudioContext) против нативного `core/build/portus-cli` на одной сцене (снимок модели); RMS ± 1 дБ, октавы ± 1.5 дБ (замер 25.10: RMS ± 0.3 дБ, октавы ± 1.1 дБ).
- `python3 tools/render.py ["()=>{…}"] [--world 2] [--onsets]` — офлайн-рендер звука (Tenebrae или удар по пластине Cymatica), RMS и время расчёта; `--onsets` — узор из 4 ударов на 120 BPM, интервалы между ударами и разброс (было 0.68 мс).
- `node --test tools/test-plate.mjs` — тесты звука пластины в Node (через `vm`, без зависимостей). Помощники секвенсера Cymatica (бывший `test-seq.mjs`) — в `tools/models/cymatica.test.mjs`.
- `node --test tools/test-models.mjs tools/models/*.test.mjs` — тесты моделей: хоста (LFO строк) и миров из `worlds/` (с шага 4 рефакторинга).
- Нужен Playwright: `pip install playwright && playwright install chromium`. На Mac в системном python его нет — временный venv в scratchpad (`/opt/homebrew/bin/python3 -m venv pw && pw/bin/pip install playwright`), браузеры уже в `~/Library/Caches/ms-playwright`. В облачной сессии Playwright и Chromium уже стоят в системном python (`/opt/pw-browsers`); `playwright install` там не качает.
- Известные падения не от мержа: `tools/test-follow.mjs` «cymatica: play sends the lock before the seq message» — падает и на чистой `native`; `test-arcadia-core.mjs` «land: … stays cheap» — тайминг, краснеет при параллельном `node --test` по всем файлам (один проходит с запасом ×10); `shot.py audio` («the Tenebrae planet survives») изредка падает в большой серии сценариев, одиночные прогоны зелёные.
- Нестабильно само по себе (и до модулей): `test-plate.mjs` «first process is cheap» и `sdk blocks (native)` в общем прогоне (замеры времени; отдельно проходят), `webmidi` под нагрузкой (тики идут пачками по таймеру; сетка ± 1 %, прежняя версия — так же); сценарий `tria` проходит лишь в 20–50 % прогонов (двойной тап по летящему телу; LFO *steps* на gravitas — окно 1.2 с против периода ~2.5 с; в облачной сессии 23.10 двойной тап не попал ни разу из 20 — у v176 так же; «после корзины тихо» изредка — стеклянный колокол звенит до 2.9 с), `triaenergy` изредка (кубик сводит тела в тесную пару) — сравнивать вперемежку со старой версией, по 10 прогонов; `render.py` для секвенсеров (Portus) и Firmamentum гуляет на ±5–20 % от прогона к прогону — сравнивать по нескольким прогонам, состояние задавать `restore(снимок)`, а не `dice()`.
