# Проверка

Вынесено из `CLAUDE.md` (26.10): все тесты, сверки, сценарии и известные нестабильные места.

`python3 -m http.server 8765` в корне, затем:

- `core/build.sh` собирает всё, включая `t2d.wasm`, и в облачной сессии (emscripten из apt, см. ниже); собранный `t2d.wasm` коммитится вместе с правкой ядра. Портус: `node --test tools/test-portus-core.mjs` — wasm против нативного `portus-cli` (расхождение 0) и сцена действий фасада = снимок ядра; модель — `tools/models/portus.test.mjs` (эталон `tools/ref/portus-model.js` и фасад над ядром, случайные правки).
- `core/build.sh && node --test tools/test-goetia-core.mjs tools/test-firm-core.mjs tools/test-ocean-core.mjs tools/test-mono-core.mjs tools/test-horo-core.mjs tools/test-arcadia-core.mjs tools/test-tria-core.mjs tools/test-transport.mjs tools/test-sdk.mjs` — сверка ядер с эталоном (render-cli и `t2d.wasm`, 1e-6; MIDI-часы ядра против прежнего JS), пара минут. Шины Monochordum и Arcadia и звук Tria против прежней Web Audio — `python3 tools/mono-bus.py`, `python3 tools/arcadia-bus.py`, `python3 tools/tria-bus.py` (браузер, при запущенном сервере); `sdk::Param` против AudioParam Chromium — `python3 tools/param-check.py` (сервер не нужен). Emscripten в облачной сессии — из apt (3.1.6, `apt-get install emscripten`): свежий emsdk не скачивается; `build.sh` понимает обе версии.
- Inferno: `node --test tools/models/inferno.test.mjs` — модель против эталона `tools/ref/inferno-model.js` и ядра `t2d.wasm` (19 тестов); звук против прежнего JS на Web Audio — `python3 tools/inferno-compare.py` (браузер, при запущенном сервере; эталон — `tools/ref/inferno-engine.js`).
- Без emscripten (облачная сессия, прокси режет его скачивание): `pip install ziglang` → `python -m ziglang c++ -target wasm32-wasi … -mexec-model=reactor` собирает `t2d.wasm` для проверки (импорты WASI — заглушки); тесты берут его через `T2D_WASM=/путь/t2d.wasm`, в прод идёт только сборка `core/build.sh` (emcc). `tools/inferno-compare.py` — сверка звука Inferno с прежним JS (RMS, полосы).
- `python3 tools/shot.py <сценарий>` (solniger, vol, planets, tenscale, ring, worlds, sun, hole, legenda, startmap, audio и по сценарию на мир, в том числе arcadia и portus — см. `docs/worlds/`) — сценарии касаний (CDP touch, 390×844) с проверками (провал или ошибка на странице — код выхода 1), скриншоты в `.shots/` — **смотреть их глазами** (Read на png). Сценарий `audio` (`sc_audio`): после `restartAudio` свежих сообщений ядру — не больше **60** (мир I теперь тоже шлёт через ядро: FX, LIVE/ON активных голосов, VOICE всех шести, фейдер слота 1; замер 26.10 — 47–48, было 36); настоящее доказательство рестарта — новый `ctxId`, а не число сообщений. Сценарий `tenscale`: тап по ладу в Tenebrae — ни одного VOICE слота 1, пока у ядра старый лад (лад уходит до голосов кадра).
- `python3 tools/natura-bus.py` — то же для Natura (прежний движок `tools/ref/natura-engine.js` + модель `tools/ref/natura-model.js` в Chromium против `core/build/natura-cli`, восемь случаев, в том числе дерево; `node --test tools/test-natura-core.mjs` — wasm = нативное).
- `python3 tools/tenebrae-bus.py [сцена …]` — звук Tenebrae (мир I, слот 1): эталон `tools/ref/tenebrae-engine.js` (прежний звук на узлах Web Audio) в Chromium (`tools/ref/tenebrae-bus.html`, OfflineAudioContext, действия — в начале блока 128, `busEnv` — Σ огибающих живых голосов, как в ядре) против `core/build/tenebrae-cli`; 13 сцен из `tools/ref/tenebrae-scenes.js` (одна планета, wave 0.5 / 0.9, tzfm / fm / am / rm, shift +300 Гц, hole 0.7, LFO cut, 6 голосов с перегрузом, хвост OFF τ 1.6, удары солнца), сухой и посыл, L и R; RMS ± 1 дБ, октавы ± 1.5 дБ (низшая ± 2). Звук случаен с обеих сторон — мощности усредняются по 4 зёрнам (удар — 16): `Math.random` страницы от зерна, у CLI строка `seed N`; около минуты. Замер 26.10: все 52 строки `ok`, RMS ± 0.27 дБ, октавы ± 0.9 дБ (низшая ± 1.5). `node --test tools/test-tenebrae-core.mjs` — wasm = нативное на тех же сценах (замер: ≤ 3e-8) и зеркало. Скорость: `node -e "import('./tools/ref/tenebrae-scenes.js').then((m) => process.stdout.write(m.cliInput(m.SCENES.full)))" | core/build/tenebrae-cli --time >/dev/null` — сцена `full` (6 голосов, dirt 0.6, dly 0.5, rev 0.5, fm-связь, LFO) — ×24 реального времени (M4 Pro, 26.10; голос с oversample-ступенью Chromium, было ×29 с FIR 47). Что осталось другим — `docs/worlds/tenebrae.md`, «Ядро: отличия».
- `python3 tools/master-bus.py [сцена …]` (при `python3 -m http.server 8765`) — мастер ядра (`t2d_master_run`: highpass → lowpass → компрессор → колено → потолок) против цепочки узлов Web Audio из `host/audio.js` (Chromium, `tools/ref/master-bus.html`): `core/build/mix-cli` отдаёт сумму миров и микс, страница пропускает ту же сумму через веб-мастер; сцены `quiet` / `full` / `dice` (`tools/ref/master-scenes.js`); RMS ± 1 дБ, октавы ± 1.5 дБ (низшая ± 2). Замер 28.10: RMS −0.4…0 дБ (у `full` −0.4 — ядро чуть мягче Chromium без его адаптивного релиза), октавы ≤ 0.5 дБ.
- iOS-приложение (фаза 2a, `ios/app/`): `xcodegen` в `ios/app`, затем `xcodebuild test -project ios/app/T2D.xcodeproj -scheme T2D -destination 'platform=iOS Simulator,name=iPhone 16'` (имя симулятора — по `xcrun simctl list devices available`) — цель `T2DTests` (XCTest). `ios/app/shot.sh [сцена]` — сборка, запуск в симуляторе с `-shot <сцена>`, снимок `.shots/ios-<сцена>.png` (смотреть глазами, не коммитить); сцены: `firmamentum` (по умолчанию), `topbar` (лад включён — подпись под заголовком), `scales` (открыт список ладов), `legend` (открыта легенда), `undo` (тап по небу → undo через `Host` на живом ядре, число звёзд — в stdout; снимок не нужен, запуск `xcrun simctl launch --console booted dev.uvarov.t2d -shot undo`). Веб-пары — `python3 tools/shot.py firmtop` (Firmamentum: `firmtop-topbar`, `firmtop-scales`, `firmtop-legend`). Плашки 2b-2: сцены `sheet` (веер FX), `starsheet` (плашка звезды), `lfo` (панель LFO на formant, 1 Гц · 50%; в консоль — RMS выхода за 2 с по 0.25 с, лог в `.shots/ios-lfo.log`), пары — `python3 tools/shot.py firmsheet` (`firmsheet-fx`, `firmsheet-star`, `firmsheet-lfo`). Тесты 2b-2: `SheetTests` (геометрия, попадания, пад, рисование), `HostTests` (роутер плашки, жесты строк и пада, LFO звезды), `FirmamentumTests` (плашки мира), `sdk_test` (`hostLfo`, `lfo*`: формы, случайные, применение, порядок, `t2d_restore`). Тесты 2b-1 (`T2DTests`): `StoreTests` (prefs и файлы сцены, битый файл, чужая версия), `TopBarTests` (раскладка, попадания, `rootAt`, список ладов, рисование), `LegendTests` (глифы, оверлей), `HostTests` (роутер, громкость, список ладов и легенда забирают касания, приглушённое съедает касание, undo, автосохранение, `testReinitReappliesScene`), `UndoTests` (шаги, предел 10, откат лада, устаревший ответ, прерывание), `HostConstTests` (громкость, лады); дополнены `FirmamentumTests` (`cornerHit`, `restored`, легенда мира). `core/build/mix-cli` — сумма миров и микс (`t2d_mix`) в float32, ею пользуется `tools/master-bus.py`; тесты `core/app/` — в `core/tests/sdk_test.cpp` (`core/build.sh && core/build/sdk-test` → `0 failed`). На железе: `ios/app/install.sh` ставит сборку на iPhone, `python3 ios/shell/logserver.py` (порт 8766) принимает лог — строки замера (задержка, загрузка, кадр) пишутся и в `Documents/t2d.log` (файлы приложения доступны через Файлы). Замер в симуляторе 28.10: загрузка 9–13 % (макс. 16–19 %), кадр ≤ 1.8 мс; `install.sh` и поведение на устройстве не проверены.
- Ядро Tenebrae, тесты без браузера: `core/build.sh` и `core/build/sdk-test` (функции `tenebrae*` в `core/tests/sdk_test.cpp`: таблицы волн и Найквист, Hilbert-сдвиг, голос — повторное включение, крайние высоты, связи, LINKS пусто, tzfm за высотой, шина, удар, зеркало (без живых — один заголовок), смена лада после VOICE (`tenebraeScaleRetune`: частоты и tzfm — за ладом без нового VOICE, лад → VOICE со snap — до бита как лад с начала, край поля x = 0 / 1 с ладом); `Shaper` os 4 против Chromium — `tools/shaper-os4-ref.py`); нативный CLI `core/build/tenebrae-cli` (stdin — сцена, stdout — float32; `--time` — скорость); wasm = нативное — `node --test tools/test-tenebrae-core.mjs` (13 тестов).
- `python3 tools/portus-bus.py` (при `python3 -m http.server 8765`) — звук Portus: прежний движок на узлах Web Audio (`tools/ref/portus-engine.js`, Chromium, OfflineAudioContext) против нативного `core/build/portus-cli` на одной сцене (снимок модели); RMS ± 1 дБ, октавы ± 1.5 дБ (замер 25.10: RMS ± 0.3 дБ, октавы ± 1.1 дБ).
- `python3 tools/render.py ["()=>{…}"] [--world 2] [--onsets]` — офлайн-рендер звука (Tenebrae или удар по пластине Cymatica), RMS и время расчёта; `--onsets` — узор из 4 ударов на 120 BPM, интервалы между ударами и разброс (было 0.68 мс).
- `node --test tools/test-plate.mjs` — тесты звука пластины в Node (через `vm`, без зависимостей). Помощники секвенсера Cymatica (бывший `test-seq.mjs`) — в `tools/models/cymatica.test.mjs`.
- `node --test tools/test-models.mjs tools/models/*.test.mjs` — тесты моделей: хоста (LFO строк) и миров из `worlds/` (с шага 4 рефакторинга).
- Нужен Playwright: `pip install playwright && playwright install chromium`. На Mac в системном python его нет — временный venv в scratchpad (`/opt/homebrew/bin/python3 -m venv pw && pw/bin/pip install playwright`), браузеры уже в `~/Library/Caches/ms-playwright`. В облачной сессии Playwright и Chromium уже стоят в системном python (`/opt/pw-browsers`); `playwright install` там не качает.
- Известные падения не от мержа: `tools/test-follow.mjs` «cymatica: play sends the lock before the seq message» — падает и на чистой `native`; `test-arcadia-core.mjs` «land: … stays cheap» — тайминг, краснеет при параллельном `node --test` по всем файлам (один проходит с запасом ×10); `shot.py audio` («the Tenebrae planet survives») изредка падает в большой серии сценариев, одиночные прогоны зелёные.
- Нестабильно само по себе (и до модулей): `test-plate.mjs` «first process is cheap» и `sdk blocks (native)` в общем прогоне (замеры времени; отдельно проходят), `webmidi` под нагрузкой (тики идут пачками по таймеру; сетка ± 1 %, прежняя версия — так же); сценарий `tria` проходит лишь в 20–50 % прогонов (двойной тап по летящему телу; LFO *steps* на gravitas — окно 1.2 с против периода ~2.5 с; в облачной сессии 23.10 двойной тап не попал ни разу из 20 — у v176 так же; «после корзины тихо» изредка — стеклянный колокол звенит до 2.9 с), `triaenergy` изредка (кубик сводит тела в тесную пару) — сравнивать вперемежку со старой версией, по 10 прогонов; `render.py` для секвенсеров (Portus) и Firmamentum гуляет на ±5–20 % от прогона к прогону — сравнивать по нескольким прогонам, состояние задавать `restore(снимок)`, а не `dice()`.
