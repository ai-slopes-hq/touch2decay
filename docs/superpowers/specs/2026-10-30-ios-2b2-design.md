# iOS-приложение — фаза 2b-2: плашки FX и LFO строк (каркас)

**Дата:** 2026-10-30 · **Статус:** согласовано с автором в чате, ждёт ревью файла · **Фаза:** `docs/native-ios-plan.md`, фаза 2, часть b, срез 2 из 3

Фаза 2b (хост-экраны) разделена на три среза, у каждого своя спека, план и приёмка на iPhone:
- **2b-1** (сделана 28.10, принята автором 30.10) — роутер хоста, верхняя строка, легенда, кубик и корзина, громкость, undo, автосохранение сцены;
- **2b-2** (эта) — оболочка плашек (`sheet`), плашка FX мира, LFO строки; в ядре — LFO строк по правилам веба;
- **2b-3** — карта Universum, микшер и мастер, concordia, панель audio, уровни каналов в ядре, настройки микшера / audio / link в файле.

## Цель

В Firmamentum на iPhone веер FX и LFO строк работают как в вебе: кнопка FX открывает плашку снизу, строка тянется вбок и звук меняется; удерживаешь звезду — её плашка с шестью строками, «~» справа ставит LFO на строку, у LFO полоса форм и пад (вправо — скорость, вверх — глубина); LFO идёт и при закрытой плашке, и в фоне.

Готово, когда: на iPhone автора кнопка FX открывает плашку, строки тянутся и слышно; удержание звезды открывает её плашку так же, как в вебе; «~» ставит и снимает LFO на строке любой плашки, LFO слышно при закрытой плашке и при заблокированном экране; картинка плашек и панели совпадает с вебом (пары снимков); все проверки ниже зелёные.

## Решения (с автором, 30.10)

1. **LFO строк — в ядре, по правилам `host/sl.js`**, а не на кадрах Swift (вариант «на кадрах, как 2a» отвергнут автором). В вебе `slTick` идёт кадром и шлёт значение в мир; в приложении это значит, что LFO рвётся на каждом пропуске кадра, а в фоне стоит. LFO — часть звука, значит живёт в аудиопотоке рядом с `modelTick`.
2. **Строка LFO привязана к строке мира.** `add` берёт базовое значение у мира (Swift спрашивает `t2d_world_value`, затем `addLfo`), `lfoTick` (раз в блок, где `modelTick`) шлёт миру новым кодом `ACT_LFO` ключ и значение — мир записывает его так же, как `SET` / `FX`. Никто не забывает применить значение, база живёт в ядре.
3. **Значение снимают с мира, а не хранят в Swift:** в вебе фасад знает состояние, в iOS его знает мир; поэтому `t2d_world_value` — запрос к миру (`World::value(i, key)`), а не к зеркалу.
4. **Снять LFO** — миру уходит `base` (как `slRemove` в вебе). **Гасить** LFO: закрытие звезды — **по ID строки** (`firm-s<слот>-<id>`, `view.js:68`): `heard` Firmamentum отдаёт id закрытых звёзд, `FirmamentumView` собирает ID и гасит точно, а не по слоту (вариант «по слоту, грубее» отвергнут автором); restore мира — по слоту (сцена сменилась, строки другие; гасим до restore, иначе LFO взведётся на вновь созданную строку). Корзина (`CLEAR`) идёт через restore сцены, отдельного пути не нужно.
5. **Порядок не важен:** `addLfo` вызывается прямо из UI-потока (не кольцом) — действие LFO не касается касаний и звука в первый блок. Кольцо — для действий мира; LFO — настройка хоста.
6. **Снимок LFO для пада** — числа (idx, morph, rate, depth, u, shape, base), строки id / key картинке не нужны: панель знает свою строку.
7. **`reset` двойным тапом** переносим только если у мира он есть: у веера Firmamentum и у плашки звезды `reset` нет — двойной тап у них ничего не делает, как в вебе.
8. **Охват строк — веер FX и своя плашка звезды при удержании** (решение автора): LFO есть на всех строках обеих плашек. У звезды `keys` — `h, u, win, mask, lvl` (`view.js:73`), формы `random`; у веера — все 7 FX-строк, формы `random` (`view.js:191`).
9. **Из отложенного 2b-1** сюда входят: кнопка FX живая (`hasFx`), дуга громкости эффектов (`fx.arc()`), подсветка нажатия FX. Остальное (вспышка undo, приглушение корзины при звучащем мире, реестр миров, хеш сборки в замерах) — не 2b-2, остаётся в `docs/ios-2b-deferred.md`.

## Часть 1. Ядро: LFO строк по правилам веба

**`sdk::RowLfo` / `WaveMorph`** (`core/sdk/lfo.hpp|.cpp`) — привести к `host/sl.js` и `host/waves.js`:
- поля: `id` (строка ≤ 15), `key` (≤ 7), `slot` (номер мира), `base`, `morph`, `rate`, `depth`, `u`, `seed`, `shape`; значения по умолчанию как `slAdd`: classic — `0 / 0.8 / 0.3`, random — `0.6 / 0.4 / 0.3`.
- **Морфинг classic — треугольная интерполяция** (`morphFn`), не линейная (`lfo.cpp:88`);
- **random:** `steps` и `smooth` берут номер периода от `u`, а не от `phase` (`lfo.cpp:63` — сейчас всегда 0-й период); `ramp up/down` — от периода.
- `value()` — `clamp(base + depth·0.5·sample(u mod 1))`, как `slTick`.

**`Host`** (`core/host/host.hpp|.cpp`):
- `int addLfo(int slot, const char* id, const char* key, double base, int shapes)` — возвращает индекс или `−1`;
- `void lfoSpec(int idx, double morph, double rate, double depth)`; `double lfoValue(int idx)`, `double lfoPhase(int idx)`;
- `void removeLfo(int idx)` — миру `ACT_LFO` с `base`;
- `void lfoTick(double dt)` — `u += dt·rate`; значение — миру `action(ACT_LFO, 0, [keyIndex, v], 2)` прямым вызовом (мы в аудиопотоке, мир в том же потоке);
- `int lfoCount()`, `bool lfoState(int i, sdk::RowLfo&)` — снимок для UI;
- `void clearLfos(int slot)`, `void clearLfos(int slot, const std::string& id)` — restore и закрытие звезды;
- `prepare` — `reserve` под максимум; `add` сверх ёмкости — `−1` и счётчик.

**Код `ACT_LFO`** — общий для миров SDK (`core/sdk/world.hpp`, вместе с документацией `action`): `action(ACT_LFO, 0, [key, v], 2)`. Мир, который его не знает, игнорирует (Cymatica, Tenebrae — проверка в тестах). Firmamentum обрабатывает: `key` 0…5 — как `SET` (`cyc, win, mask, lvl, h, u`), 6…12 — как `FX` (`scintilla … hall`).

**`World::value(int i, int key)`** — новое в интерфейсе (`core/sdk/world.hpp`): базовое значение строки `key` у объекта `i` (звезды / круга / планеты), `NaN` — нет такого объекта или ключа. **`i` нужен:** у плашки звезды один и тот же ключ (`h`) у каждой звезды свой. Для строк-эффектов объекта нет — `i = −1`. Firmamentum: `i ≥ 0` — звезда `model_.find(i)` и поле по `Key` (`CYC, WIN, MASK, LVL, H, U` → `cyc, win, mask, lvl, h, u`, `h`/`u` — как `SET`), `i = −1` — `fx_[k]`. Мир без таких строк отвечает `NaN` (все, кроме Firmamentum, в 2b-2 — проверка в тестах).

**C API:**
- `core/bridge/t2d.h`: `double t2d_world_value(int slot, int i, const char* key)`.
- `core/app/t2d_app.h` (рядом с `T2D_H_*`, но вызовы прямые, не кольцом — решение 5):
  ```c
  int  t2d_app_lfo_add(int slot, int i, const char* id, const char* key, double base, int shapes);  // −1 — не влезло; i — объект мира (−1 — у мира нет объектов)
  void t2d_app_lfo_spec(int idx, double morph, double rate, double depth);   // rate — позиция 0…1 лог-шкалы 0.03…20 Гц (как rateX в вебе)
  void t2d_app_lfo_remove(int idx);                 // миру уходит base
  int  t2d_app_lfo_take(double* buf, int cap);      // снимок: на LFO 7 чисел — idx, morph, rate, depth, u, shape, base; длина
  void t2d_app_lfo_clear(int slot);                 // restore: все LFO слота
  void t2d_app_lfo_clear_id(int slot, const char* id);   // закрытие звезды: строки с этим ID
  ```
  Порядок ключей `key` у LFO — на стороне хоста: у каждой LFO хранится `i` и `key`, а код `ACT_LFO` для мира — `key` 0…5 (как `SET`) и 6…12 (как `FX`, смещение `NKEY`) — правило в `core/host`, ключи строк у мира не разбираются. `LFO_RATE_MIN = 0.03`, `LFO_RATE_MAX = 20` — в ядре, `lerpLog` / `invLog` из `host/util.js` (нативная копия — `host.cpp`).

**Тесты ядра** (`core/tests/sdk_test.cpp`):
- `lfoClassic`: морфинг 0, 0.5, 1 на сетке u даёт числа `host/waves.js` (эталон посчитан в Node, как `scaleTable`); 9 форм, края — первая и девятая.
- `lfoRandom`: `steps` на u = 0.2 / 1.2 / 2.2 — три разных значения (сейчас — одно, `lfo.cpp:63`); `smooth` непрерывен на границе периода.
- `lfoApply`: Firmamentum, звезда, `add` на `h` с `base` из мира, `depth 0.5`, `rate 1`, 0.25 с — `World::value` звезды в пределах `base ± depth/2`, без LFO — равно `base`.
- `lfoRemove`: после снятия мир снова на `base`.
- `lfoClear`: по слоту и по ID — снятие и `base` в мире; по ID гасятся только строки с этим ID.
- `lfoCap`: `add` сверх ёмкости — `−1`, `lfoCount` не растёт, `capacity` вектора не меняется (`process` без аллокаций).
- `lfoForeign`: `ACT_LFO` на слот без обработки (Cymatica) — не падает, RMS двух прогонов равны; `t2d_world_value` у Cymatica — `NaN`.
- `appLfo`: через C API — `add`, `spec`, `take`, `remove`, `clear_id`.
- `firmHeardClose`: закрытие звезды — в записи `heard` её id; раскладка записи не ломает `Heard.parse` (сверка в Swift-тестах).
