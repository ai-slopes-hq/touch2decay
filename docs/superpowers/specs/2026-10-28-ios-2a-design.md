# iOS-приложение — фаза 2a: вертикальный срез (ядро → звук → картинка → касание)

**Дата:** 2026-10-28 · **Статус:** согласовано с автором в чате, ждёт ревью файла · **Фаза:** `docs/native-ios-plan.md`, фаза 2, часть a из 2

Фаза 2 разделена на две спеки: **2a** (эта) — вертикальный срез на одном мире; **2b** — хост-экраны (верхняя строка, карта Universum, микшер, concordia, плашки FX / LFO, легенда, панель audio, undo, сохранение).

## Цель

Нативное приложение `ios/app/` (Swift + CoreGraphics, без WebView) играет Firmamentum из ядра C++: касание → ядро → звук и картинка. Отвечает на главный вопрос фазы — тянет ли нативный стек по задержке, нагрузке и кадру.

Готово, когда: на iPhone автора тап по небу ставит звезду со звуком, звёзды двигаются и закрываются; звук идёт при заблокированном экране и переживает прерывание; в логе задержка касание→звук ≤ 20 мс, загрузка рендера ≤ 30 % бюджета, 60 fps без провалов; на слух — не хуже веба. Итог решает автор на слух, числа — подкрепление. Все проверки ниже зелёные.

## Решения (с автором, 28.10)

1. Картинка — Swift + CoreGraphics (подтверждено; снимает пометку «подтвердить перед фазой 2» в `native-ios-plan.md:9`).
2. Две спеки: 2a — срез, 2b — хост-экраны.
3. Мерило 2a — «не хуже веба на том же iPhone» + числа в логе (цели выше), не жёсткие пороги.
4. Микс и мастер — полностью в ядре, только для приложения; веб остаётся на мастере Web Audio.
5. На экране — только мир на весь экран и скрытая панель замеров (долгое нажатие в правом нижнем углу). Удержание по миру в 2a ничего не делает. Без сохранения.
6. Ядро ↔ Swift — очереди без блокировок (SPSC действий, тройной буфер зеркала), как worklet ↔ страница в вебе. Не мьютекс, не рендер вперёд.
7. Swift-view рисует прямо по зеркалу ядра, без оптимистичного фасада `model.js`: касание доходит до зеркала за один буфер (~5 мс), это меньше кадра.

## Ограничения

- Миры заморожены: перенос, не переделка. Картинка Firmamentum — по `worlds/firmamentum/view.js`; принципы «картинка = информация», «не шумно», гравюра без теней и градиентов в кадре, без жирного (`CLAUDE.md:62-70`).
- Ядро: C++17, `-ffp-contract=off` (обязателен — иначе расходится с JS), без аллокаций и блокировок в аудиопотоке. Комментарии — по-русски, плотность как в `core/sdk/`.
- Веб не меняет поведения. Правка `core/` → пересборка `t2d.wasm` (`core/build.sh`) и новая версия при пуше (`CACHE` в `sw.js` = `?v=` в `index.html`).
- Работа — в ветке `native`, в `main` не идёт.
- Сборка — Xcode 16.2 + XcodeGen на этой машине; на iPhone (iOS 26.6) — установка `ideviceinstaller` без DDI, подпись Personal Team (7 дней). Звук и задержку на реальном iPhone проверяет автор.

## Часть 1. Ядро и мост (C++)

**Общий заголовок.** `core/bridge/t2d.h` объявляет все `t2d_*`. `wasm.cpp` делится:
- `core/bridge/api.cpp` — общие функции (синглтоны Host и миров, буферы args / mbuf / str, `t2d_action`, `t2d_mirror`, `t2d_heard`, `t2d_snapshot` и т. д.);
- `core/bridge/wasm.cpp` — только emscripten: `_Exit`, атрибуты экспорта.

Нативная сборка не тянет `wasm.cpp` (его `_Exit` перекрыл бы libc). Списки исходников в `core/build.sh` обновляются; `t2d.wasm` по поведению тот же.

**Полный микс.** Новая `t2d_mix(L, R, n)`: Σ по слотам `dry × fader × trim` + возвраты ревербов → мастер → выход. Trim — поле мира в ядре для всех слотов, значения переносятся из `worlds/*/engine.js` (веб свои trim не меняет). Мастер ядра дополняется до цепочки веба: HP 30 → LPF → компрессор → 0.8·vol → ×0.5 → knee 4× → потолок. Компрессор ядра подгоняется к `DynamicsCompressor` по мерилу, побитного совпадения не требуется. Существующий путь «мастер только на `ret_`» вебом не используется — заменяется, если ничто другое на него не опирается (проверить в плане).

**Слой приложения `core/app/`** (только нативная сборка):
- `Engine` — владеет ядром (через функции моста).
- Кольцо действий SPSC (UI → аудио), фиксированной ёмкости; элемент: слот, вид, индекс, аргументы, id действия, время касания (host time). Переполнение — действие отбрасывается и считается в статистике.
- Тройной буфер зеркала и heard (аудио → UI): аудиопоток после блока публикует, UI в кадре забирает последнее.
- `render(L, R, n)` режет буфер устройства на куски по 128: применить накопленные действия → `t2d_time` → тик модели → `t2d_process(128)` → `t2d_mix`. Порядок тика согласовать с вебом (см. «Открытый вопрос»).
- Статистика в атомиках: время рендера (ср / макс за окно), id и host time блока, применившего действие, переполнения кольца. Без аллокаций.
- Наружу — `core/app/t2d_app.h` (C): `t2d_app_init(sr, seed)`, `t2d_app_render(L, R, n, hostTime)`, `t2d_app_action(...)`, `t2d_app_mirror(slot, buf, cap)`, `t2d_app_heard(...)`, `t2d_app_stats(...)`. Точные сигнатуры — в плане.

**Открытый вопрос (первая задача плана, до кода).** Веб не вызывает `t2d_model_tick` — выяснить, что двигает модель Firmamentum во времени (тик внутри `process`, действие из JS-кадра или иное). Нативный тик не должен задвоить ход модели.

## Часть 2. Приложение и звук (Swift)

**Проект `ios/app/`** — `project.yml` (XcodeGen) по образцу оболочки: iOS 17, только iPhone, портрет, команда `8N8KQ5985C`, `UIBackgroundModes: audio`, `UIFileSharingEnabled`. Bundle id `dev.uvarov.t2d` (рядом с оболочкой, не вместо). `.xcodeproj` и `build/` — в `.gitignore`, не коммитятся.

Target'ы:
- `T2DCore` — static library из исходников `core/` (без `bridge/wasm.cpp`) и `core/app/`; флаги `-std=c++17 -O2 -ffp-contract=off`; module map на `t2d_app.h`. Xcode сам собирает под устройство и симулятор.
- `T2D` — приложение.

**Звук:**
- `AVAudioSession` `.playback`, `preferredIOBufferDuration` = 256 / 48000 (≈ 5.3 мс). Выданные размер буфера и частота — в лог.
- `AVAudioEngine` → `AVAudioSourceNode` (float, стерео, планарно); рендер-блок зовёт `t2d_app_render` с `AudioTimeStamp.mHostTime`. В блоке — без Swift-аллокаций и блокировок.
- Ядро инициализируется фактической частотой движка.
- Прерывание (`interruption .ended`), смена маршрута, `mediaServicesWereReset` → перезапуск движка; если сменилась частота — переинициализация ядра (сцена теряется — в 2a допустимо). Каждое событие — в лог.
- Фон — звук при заблокированном экране.

**Установка:** `ios/app/install.sh` — `xcodebuild` → `.ipa` → `ideviceinstaller install`, как у оболочки.

**Лог:** `Log.swift` из оболочки — `Documents/t2d.log` и пачки на Mac в `ios/shell/logserver.py`, если он запущен. Раз в секунду — строка замеров (часть 4), плюс события сессии.

## Часть 3. Рисование и мир

**`Draw.swift`** — обёртка над `CGContext` с вызовами `host/draw.js`: `setTheme`, `ink`, `paper`, `ring`, `dot`, `diamond`, `hairBox`, `text`, `mapText`, `glowAt`, `drawCurve`. `glowAt` — спрайт свечения кешируется один раз (`CGImage`). Плотность — `min(screen.scale, 2)` (правило DPR ≤ 2, совпадает с эталоном `shot.py`). Без теней и градиентов в кадре. `sunGlyph` / `quarterSun` — не в 2a.

**Шрифты:** `tools/woff2-ttf.py` (fonttools + brotli, `uv run --with fonttools --with brotli`) один раз делает ttf из `fonts/*.woff2`; ttf и OFL-лицензии — в `ios/app/Fonts/`, регистрация через `UIAppFonts`. IM Fell English — красота, EB Garamond — чтение.

**Кадр:** `CADisplayLink` 60 Гц → забрать снимок зеркала и heard → `world.tick(now, dt)` → `setNeedsDisplay` → в `draw(_:)` вся сцена. Главный поток. Кеш фона — только если замер кадра покажет нужду.

**Протокол `World`** — минимум для 2a: `slot`, `theme`, `tick(now, dt)`, `draw(now, dt)`, `down / move / up(finger)`. Прочие поля веб-мира (`fx`, `legend`, `corner`, `mapShot`, …) — в 2b.

**`Touch.swift`:** таблица пальцев и константы `host/touch.js` (`TAP_MS` 220, `TAP_MOVE` 14, `DTAP_MS` 320, `HOLD_MS` 420, `HOLD_MOVE` 10). Касания — из `touchesBegan / Moved / Ended / Cancelled`, `UITouch.timestamp` идёт в действие. Долгое нажатие (`HOLD_MS`) в правом нижнем углу (44×44 pt) перехватывается до мира и включает / прячет панель замеров.

**`FirmamentumView.swift`** — порт `worlds/firmamentum/view.js`: звёзды из зеркала (`world.hpp:12-31`), вспышки из heard (как `engine.js:9-21`), действия `add` / `move` / `close` (тап по небу, сдвиг > 8 px, тап < 300 мс по звезде). Удержание ничего не делает. Тема и FX — по умолчанию.

## Часть 4. Замеры и проверка

**Задержка касание → звук** = host time блока, применившего действие, + `outputLatency` − `UITouch.timestamp`. Обе метки — `mach_absolute_time`. Не учтены тачскрин до `touchesBegan` и путь DAC → ухо (как и в вебе).

**Загрузка** = время `t2d_app_render` / длительность буфера; ср и макс за секунду.

**Кадр** — от `CADisplayLink` до конца `draw(_:)`; плюс пропуски кадров.

**Строка лога и панели** (раз в секунду):
`lat ср/макс мс · load ср/макс % · frame ср/макс мс · пропуски · буфер n@sr · звёзд N`. Панель — тонко, EB Garamond, внизу экрана, скрыта по умолчанию.

**Сравнение с вебом:** числа — против `baseLatency + outputLatency` веб-контекста на том же iPhone (веб пишет их в консоль); слух — автор тапает по звёздам в обоих.

**Проверки до iPhone:**
1. `sdk-test`: кольцо и тройной буфер под двумя потоками; `Engine` против прямого `t2d_action` — зеркала до бита; микс и мастер.
2. `tools/master-bus.py`: мастер ядра против веб-мастера на рендере Firmamentum в Chromium — RMS ± 1 дБ, октавы ± 1.5 дБ.
3. Веб не сломан: `core/build.sh` (с `t2d.wasm`), `node --test tools/test-models.mjs tools/models/*.test.mjs`, `tools/test-*-core.mjs`, `shot.py` — зелёные.
4. `xcodebuild` под симулятор — без ошибок и предупреждений в своём коде.
5. Скриншот симулятора рядом с `.shots/firmamentum.png` — сравнение глазами (сглаживание CoreGraphics и Chromium разное, попиксельно не сравниваем). Сцена та же, что в `sc_firmamentum`: приложение с аргументом запуска `-shot firmamentum` проигрывает те же действия через `t2d_app_action` с тем же зерном, затем `xcrun simctl io booted screenshot` (скрипт `ios/app/shot.sh`).

**Приёмка на iPhone (автор):** звук на тап, звёзды двигаются и закрываются; звук при заблокированном экране; прерывание (звонок / Siri) переживается; числа в целях; на слух не хуже веба.
