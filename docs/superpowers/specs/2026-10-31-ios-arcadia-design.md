# iOS-приложение — фаза 3: Arcadia на Swift

**Дата:** 2026-10-31 · **Статус:** черновик, ждёт ревью автора · **Фаза:** `docs/native-ios-plan.md`, фаза 3 (миры по одному) · **Образец:** `ios/app/T2D/Horologium/`, спека `2026-10-30-ios-horologium-design.md`; Monochordum — `ios/app/T2D/Monochord/`

## Цель

Пятый нативный мир — XII · Arcadia: гравированная карта холмистой страны, странники с петлями по рельефу, касания, плашка странника `viator`, веер FX с LFO и легенда на Swift + CoreGraphics. Страна, странники, пути, звук и шина уже в ядре (`core/worlds/arcadia/`), Swift разбирает зеркало и шлёт действия. Попутно — то, без чего мир не встаёт в нативе: картина страны из ядра (Swift не портирует `genLand`), `ACT_LFO` в ядре Arcadia и кубик в Swift.

Готово, когда: на iPhone автора Arcadia открывается с карты; тап по земле, флажок, край петли, плашка, веер FX с LFO, кубик, корзина, отмена работают как в вебе; стена (горы, холмы, леса, озёра, реки, имена) совпадает с вебом на одном зерне; пары снимков симулятор ↔ веб сходятся; проверки ниже зелёные.

## Решения

1. **Всё как в вебе** (`worlds/arcadia/view.js`; из `model.js` — константы `GX 80, GY 160, ASP 3.2, VMAX 4, SEMIS 24, K 2.4, Q1` (`:10-11`), `MONTES / LACUS / FLUMINA / FIGS / PATHS` (`:12-15`), `figPt`, `depthOf` (`:124-125`), `T_KEYS` (`:16`)): геометрия `geo / proj / unproj / at / pick / loopPts` (`view.js:12-31`), касания (`:41-82`), плашка (`:84-93`), удержание (`:94-96`), стена и рисование (`:98-268`), веер, легенда, угол (`:270-282`). Новых решений в картинке нет. Шрифты как в вебе: `mapText` — IM Fell (имена на стене курсивом 10.5, подпись «A R C A D I A» прямым 15, подписи странника), `text` — EB Garamond, плашки в `reading`. Тема — `Worlds.info(12)` (`ink 40,46,32`, бумага `224,221,198`; `WATER 46,86,104` — константа мира, как в `view.js:6`). Заголовок `Arcadia`, подзаголовок `montes · lacus · flumina` (`index.js:20`).
2. **Где код:** `ios/app/T2D/Arcadia/` — `ArcMath.swift` (константы, `bil`, `dist`, `figPt`, `depthOf`, `noteName`, имена `FIGS / PATHS`), `ArcGeo.swift` (`geo`, `proj / unproj / at / pick / loopPts`; `K 2.4`; чистый код, зависит только от `zAt`), `ArcMirror.swift` (разбор зеркала), `ArcState.swift` (чистый помощник: слоты, ожидающие слоты, собственные значения, порядок странников, след; без `Core`), `ArcPic.swift` (страна для картинки: массивы `z / lake`, вершины, озёра, реки; сборщик в фоне и кеш), `ArcDraw.swift` (стена, `drawT`), `ArcSheets.swift` (плашка `viator`, веер), `ArcadiaView.swift` (класс `World`: легенда, касания, тик). Регистрация: `Worlds.swift:29` — `view: false → true`; `App.makeView` (`App.swift:30-40`) — ветка `ArcadiaView.slotN` (12), `@State arc` рядом с `horo`; сцены `-shot arcadia*` — `App.swift:78` (список) и новая `shotArc` рядом с `shotHoro` (`:213-226`); `project.yml:60` (источники теста) — добавить `T2D/Arcadia`.
3. **Зеркало** (`core/worlds/arcadia/world.cpp:131-146`, `world.hpp:25`, 65 чисел, буфер ≥ 80): `fx[7]` (`relief, pace, wind, chorus, phaser, spread, hall`), `seed` (зерно, какой будет страна — `want_`), `pending` (страна растёт), затем 4 слота по 14: `on, u, v, oct, r, fig, mode, sp, lvl, f, cx, cy, rs, gain` (`f` — нота ядра, Гц; `cx, cy, rs` — центр и радиус петли; `gain` — уровень). `heard` = 0 (`world.hpp:36`), читать нечего. Читатель зеркала внедряется (тесты — на фейке), как у Horologium.
4. **Действия** (`world.hpp:22`) — через `Core.action(slot 12, …)`: `ADD 0 (i = слот, [u, v, oct, r, fig, mode, sp, lvl])`, `DROP 1 (i)`, `MOVE 2 (i, [u, v])`, `SET 3 (i, [key, v, route 0/1])` (`key` — индекс `T_KEYS`: `u 0, v 1, oct 2, r 3, fig 4, mode 5, sp 6, lvl 7`; `route 1` — только при смене `mode`, как `setT(…, k === 'mode')`, `view.js:90`), `FX 4 (i = индекс Fx, [v])`, `LAND 5 ([seed])`, `CLEAR 6`. LFO — не `Core.action`, а общий путь хоста (`Host.swift:87-94`: `lfoAdd` и т.д. → ядро шлёт `ACT_LFO`, решение 6). **Индекс Fx — позиция в 7-элементном массиве, не строка веера:** у `hall` — 6, `spread` (5) в вебе в веере нет.
5. **Картина страны — из ядра, не порт `genLand`** (`model.js:30-123`). Рисование и касания нужна страна, которой у зеркала нет (оно хранит только зерно). Ядро:
   - **чистая функция для картинки** в `core/app/t2d_app.{h,cpp}` — это ABI Swift (`core/bridge/api.cpp` — wasm, там остаётся только `t2d_arc_land`): `int t2d_app_arc_pic(unsigned seed, float* z, float* lake, double* meta, int cap)` — строит страну целиком (`LandGen::run` в своей `Land` на куче, не в `Model`), копирует `z` и `lake` (по 80·160 float) и пишет `meta`; без общего состояния с аудио, звать с любого потока, кроме звукового (~20 мс, `world.cpp`/`land.hpp:4`). Возврат — длина `meta`; `cap` мал — 0. `meta` (doubles): `np, nl, nr`, затем `np × (u, v, h, имя)`, `nl × (u, v, w, level, pond, имя)`, на реку `(n, имя, n × (u, v))`; имя — индекс в таблице ядра, `-1` — без имени; текст — `const char* t2d_app_arc_name(int kind, int idx)` (`0 горы, 1 озёра, 2 реки`; таблицы `MONTES / LACUS / FLUMINA` переезжают в `land.hpp`) — имена не дублируются в Swift. Предел: 8 вершин, ≤ 8 озёр (`LMAX`), ≤ 3 реки по ≤ 191 точке → `meta` ≤ ~1300 чисел;
   - **`LandGen` получает необязательный приёмник `Pic*`** (`start(seed, out, pic = nullptr)`): звуковой путь передаёт `nullptr` и не платит ни такта (кусок ≤ 0.3 мс, `land.hpp:28`). Со `Pic` `trace()` / `lake()` / `norm()` дописывают озёра (`u, v, w, level, pond` — те же `lakes_`, `level` ставит `lake(k)`), реки и вершины. **Подводные камни, найденные при чтении:** (а) `genLand` не тратит `rng` ни на имена (`model.js:53, 85, 121` — арифметика от зерна: `LACUS[(seed + k) % 4]`, `FLUMINA[(seed + k·3) % 6]`, `MONTES[(seed + k·5) % 8]`, `k < 3`), ни на вершины (`:111-121` — скан готовой `z` после нормировки), поэтому звук остаётся бит в бит; (б) имя реки зависит от **номера цикла `k`**, а ядро теперь отбрасывает реки с `n ≤ 12` (`land.cpp:133`) и теряет `k` — его надо записать вместе с рекой (иначе вторая река при отброшенной первой получит чужое имя); (в) пруды (`pond`) идут в `lakes` после основных озёр и без имени (`model.js:84`); (г) зерно для имён — `uint64`, не `uint32` (`seed + k·5`); (д) вершины — `z` во `float`, сравнения `h < 0.4`, `> h`, порог `dist > 0.25`, устойчивая сортировка по убыванию `h`, как в JS (`std::stable_sort`);
   - **`routeOf` — чистая функция на `Land`:** `int routeOf(const float* z, const float* lake, double u, double v, double mode, double* out)` в `land.cpp` (число чисел в `out` — как `Trav.n`, 0 при `mode < 3`); `Model::route` (`model.cpp:52`) становится её вызовом — один код на звук и мост, звук не меняется (`test-arcadia-core.mjs`, 1e-6). Мост: `int t2d_app_arc_route(const float* z, const float* lake, double u, double v, int mode, double* out, int cap)` (`cap < RMAX_PTS = 182` — 0). Копии `z / lake` держит Swift; ядро ничего не помнит;
   - веб не меняется: `genLand` фасада остаётся; ядро с `Pic` — тот же код; `core/build.sh` пересобирает `t2d.wasm`.
6. **`ACT_LFO` в ядре Arcadia** (`world.cpp:51`; образцы `firmamentum/world.cpp:43-55`, `horologium/world.cpp:29-35`; `core/host/host.cpp:264` шлёт `action(ACT_LFO, obj, [key, v], 2)`, `v` 0…1):
   - **`obj = −1`** — строка веера: `key 0…6` → `model_.setFx(key, v); applyFx()` (в том числе `spread` 5, хотя его строки нет);
   - **`obj = слот 0…3`**, слот жив: `key 3` (`R`) → `r = 0.03 + 0.57·v`, `key 6` (`SP`) → `sp = 0.6·v`, `key 7` (`LVL`) → `lvl = v` (те же формулы, что `get / set` плашки, `view.js:89-90`), затем `sendT(obj, true, false)` — без пересчёта пути (как `setT` без `route`); прочие ключи (`u, v, oct, fig, mode`), мёртвый слот, `obj ≥ VMAX` или `obj < −1`, `n < 2` — пропуск;
   - **коды `SheetRow.code`:** веер — `relief 0, pace 1, wind 2, chorus 3, phaser 4, hall 6`; плашка `viator` — `orbit 3, range 6, level 7`, строки без LFO (`octave, figure, path`) — `−1`. Это значения `Key` (`model.hpp:19`) для странника и `Fx` (`:18`) для веера: obj различает (3 у веера — `chorus`, у странника — `r`).
7. **Своих значений до зеркала почти не держим, но у Arcadia есть три исключения** (зеркало ~60/с, у Swift нет числа «применено сообщений», как у веба `applied`, `model.js:231-240`); всё — в `ArcState` (чистый, на вход время и зеркало):
   - **слоты:** странник живёт, если в зеркале `on` **или** слот ожидает (`pending[slot]` с меткой времени). `ADD` выбирает первый слот, не занятый ни зеркалом, ни ожиданием, ни логически (после `CLEAR` в том же кадре слоты свободны) — два пальца в одном кадре и кубик сразу после `CLEAR` не сталкиваются; `Core.action == false` (кольцо полно) — слот не занят, странника нет. Ожидание снимается, когда зеркало показало `on` (для `DROP` — `off`) или через 0.25 с без ответа (потерянное действие не держит слот вечно). Порядок странников (`order`) — порядок добавления, как массив `travellers` веба (от него зависят `homeAt` при равных расстояниях и порядок рисования при равных `v`); при разборе зеркала новые слоты без Swift-добавления (отмена) идут по возрастанию слота — так их заново добавляет `World::restore` (`world.cpp:88`);
   - **собственные значения:** пока палец тянет флажок (`MOVE`) или край (`SET r`), а также пока плашка меняет строку, Swift рисует и отвечает из своих `u, v, r, …`, не из зеркала (нет отставания на кадр); зеркало берёт верх, когда сошлось (`|Δ| < 1e-9`) или через 0.25 с после последнего своего действия по слоту (аналог `tAt` веба);
   - **fx** — так же (`fxAt`): значение пальца/плашки, пока не сошлось с зеркалом или не прошло 0.25 с. LFO меняет fx и `r / sp / lvl` в ядре — зеркало их приносит, и собственные значения не мешают, если по ним сейчас нет действий.
8. **Касания** (`view.js:41-96`; пороги — как есть, не общие `Touch.tapMs`): `flagAt` — `at(t.u, t.v)`; `homeAt` — ближайший флажок в радиусе 24 по двум точкам (`(x, y)` и `(x − 4, y + 14)` от основания), по `order`; `rimAt` — точка петли (`loopPts` 48) ближе 12 px, `r < 0.06` пропускаем. Порядок в `down`:
   - **край петли** (`rim && hd > 12`, где `hd` — расстояние до ближайшего флажка) важнее флажка, если палец не прямо во флажок: тянешь — `SET r = clamp(dist(центр, unproj), 0.03, 0.6)`, центр — `cx, cy` из зеркала (запас — дом);
   - **флажок** — `home`: сдвиг > 8 px (`moved`) — `MOVE` в `clamp(±0.98)` по `pick(clamp(x, fx0, fx1), max(y, hor − 30))` или `unproj(x, hor)`; тап (< 300 мс, без сдвига, не `fresh`, плашка не открыта) — `DROP`; удержание `HOLD_MS 420` (`Touch.holdMs`) без сдвига — плашка `viator`;
   - **земля** (`x ∈ (fx0, fx1)`, `y < bot`, `pick` не небо): `ADD` с `(u, clamp(v, −0.98, 0.98))` и умолчаниями `r 0.16, fig 0, mode 2, sp 0.22, lvl 0.8, oct 0`; палец сразу — `home` с `fresh` (подъём странника не убирает, подпись видна). Мест нет (4 странника) — палец `none`;
   - угол — солнце четвертью справа сверху (`y > sun.y` и `hypot < sun.r + 12`, `view.js:282`) ведёт на карту;
   - пальцы независимы по `Finger.id` (один держит флажок, второй ставит странника — оба работают); подпись при касании (`held`) — по слоту, последний палец побеждает, как `held` Map веба.
9. **Плашки и веер** (`view.js:84-93, 272-278`):
   - **`viator`** (hint `wanderer — tap outside to close`): строки `octave, orbit, figure, path, range, level` (ключи `oct, r, fig, mode, sp, lvl`); `get`: `(oct+1)/2`, `(r − 0.03)/0.57`, `fig/2`, `mode/4`, `sp/0.6`, `lvl`; `set` — обратно (`round(v·2) − 1`, `0.03 + 0.57v`, `round(2v)`, `round(4v)`, `0.6v`, `v`); тексты `octave −1/0/+1`, `circle/eight/knot`, `still/circuit/wander/river/summit`, `N%` (orbit — `r`, range — `sp/0.6`, level — `lvl`). LFO только на `orbit, range, level`, `obj = слот`, форма `random` (`shape 1`). Читает свои значения (решение 7);
   - **веер** `aether`: секторы `relief 190°, pace 160°, wind 140°, chorus 120°, phaser 100°, hall 80°`, `arc: fx.hall`, LFO на всех шести (`obj −1`, `random`); тексты `pace` — `N s` (`1/(0.01·40^pace)`, целое), `wind` < 0.01 — `calm`, `chorus / phaser` < 0.01 — `off`, прочие `N%`. `spread` в веере нет — читается и пишется ядром только как есть в зеркале (0.6 по умолчанию);
   - **легенда** — 7 строк `view.js:279-281` (`tap, up, drag, tap, hold, tap, tap`).
10. **Кубик в Swift**, как `dice()` веба (`model.js:206-216`), ГСЧ внедряется (в приложении — системный, в тестах — по зерну), порядок вызовов тот же: `seed = (R·2147483646)|0`; `n = 2 + ⌊R·2⌋`; на странника: до 20 попыток `u = 1.6R − 0.8, v = 1.5R − 0.75` пока `lake(u, v) ≥ 0.2` (20-я попытка берётся как есть); затем по порядку `r = 0.08 + 0.3R`, `fig = R < 0.6 ? 0 : 1 + ⌊2R⌋`, `mode = 1 + ⌊4R⌋`, `sp = 0.12 + 0.3R`, `oct = R < 0.25 ? −1 : 0`. Страна новая, а `lake` нужен именно по ней, поэтому: (1) зерно → `ArcPic` строится в фоне (`t2d_app_arc_pic`); (2) по готовности, в главном потоке: `CLEAR`, `LAND seed`, 2–3 `ADD` в точки по **новой** стране (слоты — решение 7: после `CLEAR` слоты 0…n−1). Повторный кубик, пока страна строится, отбрасывает прежний результат (счётчик поколений). Страна не совпадёт с вебом при том же зерне веба: веб — `Math.random`, натив — свой ГСЧ; сцены снимков кубик не используют.
11. **Корзина, undo, LFO.** `clear()` — как веб `clear()` (`model.js:198`): `DROP` всех живых по `order`; `objGone(slot)` на каждого (LFO странника снимает хост, `Host.swift:90`; открытая плашка этого странника закрывается). То же — при `DROP` касанием, кубике и когда зеркало показало `on → off` у слота без нашего `DROP` (отмена, `restore`). **`restored()`** (undo, `restore` ядра): слоты после `restore` пересобираются (`world.cpp:77-98`: `clear`, потом `freeSlot` по возрастанию), поэтому слот ≠ прежний странник — LFO по `obj = слот` теперь чужие: `objGone` для всех слотов, пальцы и следы сброшены, ожидания и собственные значения очищены, `ArcPic` заново по зерну зеркала, если оно сменилось. Веб на этом месте держит LFO за `id` странника, натив — за слот: LFO странников при отмене не переживает (в вебе тоже: `restore` → `clear` → `lfoClear`).
12. **След блуждания** — картинка, в Swift (`model.js:200-205`): раз в 0.12 с (по накопленному `dt` ≤ 0.1) всем одновременно, для живых странников с `mode == 2` точка `(cx, cy)` из зеркала в кольцевой буфер ≤ 40; `mode ≠ 2` или нет центра — буфер пуст; `MOVE` (касание) — пуст. Рисуется при ≥ 3 точек. Предвыделен на слот.
13. **Рисование** (`view.js:98-268`):
    - **стена** — `CGImage` (рисуется в `CGContext` размером `W × H × DPR`, DPR ≤ 2, шрифты через тот же `Draw`, что у `HoroDraw`); ключ как `view.js:137`: `W×H×DPR | hor | gb | Wh | seed | pcs | root`. Пересобирается **в фоне** при смене зерна, размера, лада; старый образ остаётся, пока новый не готов (до первого — заливка бумагой `PAPER`). Содержимое — 1:1: крап, облака, дальние хребты (`rs` LCG 16807, `rs = 5`), борозды, штриховка озёр, берег по мелкой экранной сетке (`SC 3`, дважды: `0.5` и `0.15`), реки, ряды значков рельефа (`mountain / hill / tree / tuft`; свой LCG `sd = seed % 2147483646 + 1`, умножение 16807 в `Int64`, порядок вызовов `rnd()` как в JS — от него зависит, где стоят значки), имена без наложений, рамка Таро, горизонт, подпись, деления лада по левой рамке (ступени лада длиннее). Рельеф, озёра и реки — из `ArcPic`;
    - **в кадре** (`drawT`, `view.js:234-259`): путь пунктиром (по `mode`), привязь, петля поднята холмами (120 точек) и её тень (61), сканер (`ph = (now·0.00022·√(f/55)) mod 1`, `f` — из зеркала), флажок с волной, при касании — `noteName(f) · Hz`, `orbit N%` / `path · figure`, засечка своей ноты на левой шкале. Дальние странники рисуются раньше (сорт по `v` убыв.), солнце — последним (`quarterSun`);
    - **путь** `mode ≥ 3` — `t2d_app_arc_route` по `ArcPic`, кеш на слот с ключом `(seed, u, v, mode)`: пересчёт при `ADD`, `MOVE`, смене `mode`, новой стране; `mode 1` — эллипс `sp`, `mode 2` — след;
    - производительность: никакого `shadowBlur`; градиентов на кадр нет; полноэкранных проходов нет, кроме `drawImage` стены; точки петель, путей, теней — предвыделенные буферы на слот (`loopPts` пишет в буфер, не возвращает массив); `dt` для картинки — не больше 0.1 с; в кадре ни одного `Array`/замыкания на странника.
14. **Лад** нужен стене (деления: `on = !pcs || pcs.contains((k + root) % 12)`, длина 6 / 3, яркость 0.6 / 0.25; ключ стены) и ничему больше: нота — `f` из зеркала (ядро считает `hzOf` с ладом хоста), `semiOf` в Swift не портируем. Мир берёт `pcs, root` из `World.scale(pcs:root:)`; `enter()` не нужен.
15. **Не делаем:** Swift-порт `genLand` (картина — из ядра); совпадение кубика с вебом при одном зерне; LFO странников, переживающие отмену; `spread` в веере (в вебе его нет); нативные имена на карте мимо ядерных таблиц; сохранение следа в сцене; шаги `T.tempoFrom` и прочее общее, чего у Arcadia нет.

## Риски

- **Стена** (`view.js:136-233`): ~сотни значков, марширующие квадраты по 100×200 клеток дважды, ~260 крапин, шрифты; на iPhone — десятки миллисекунд в фоне, но первая сборка при входе видна как бумага без рисунка; кадр без стены допустим один раз, затем образ кешируется. Смена лада пересобирает её целиком.
- **`genLand` ~20 мс** (в фоне): кубик и отмена со сменой зерна держат старую картину ~одну-две стены; пока строится — странники в новой точке рисуются по старому рельефу, как веб до готовой страны.
- **Отставание собственных значений 0.25 с** при затянувшемся тике звукового потока даёт один мигающий кадр у флажка: терпим.
- **Нота при тяге** — из зеркала (`f`), на кадр позже позиции флажка; в вебе подпись мгновенная. Если автору мешает — порт `semiOf` с `pcs`.
- **`LandGen` + `Pic`** трогает горячий код звука (по `nullptr`); тест бит в бит и `sdk-test` обязательны перед выкладкой.
- Снимки — симулятор; звук, жесты на ощупь и производительность проверяет автор на iPhone.
