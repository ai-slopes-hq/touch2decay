# Tenebrae · шаг Б фазы 4 — модель в ядро C++

Дата: 03.11.2026. Ветка `native`. Продолжение шага А (`2026-11-03-tenebrae-model-extract-design.md`): модель мира I уже чистый модуль `worlds/tenebrae/model.js`; теперь она переезжает в ядро по образцу Firmamentum / Natura / Cymatica. Дизайн одобрен автором в чате 03.11 («ок»).

## Цель

Модель Tenebrae живёт в `core/worlds/tenebrae/` и ведёт голоса сама; веб и будущий Swift (шаг В) зовут её действия и читают зеркало и `heard`. В ядре появляются `snapshot` / `restore` Tenebrae — на iOS заработает отмена. **Веб ведёт себя так же**: звук, жесты, картинка; случайные числа другие (зерно ядра), распределения те же.

Не входит: Swift (шаг В, Mac автора), перенос view и жестов из `app.js`, изменения поведения сверх перечисленных ниже защит.

## Источник истины

- Поведение — `worlds/tenebrae/model.js` (шаг А) после двух правок (раздел «Правки модели до переноса»). Его копия становится эталоном `tools/ref/tenebrae-model.js`; C++ — порт эталона один в один (порядок вызовов `rng`, порядок команд голосам, формулы). Паритетные хелперы — `core/sdk/jsmath.hpp`.
- Звук голосов, шины, эха, ударов — нынешнее ядро (этап 1), не меняется.
- Правила мира SDK — `docs/architecture.md` («Мир SDK»), `docs/sdk-rules.md`, `core/sdk/world.hpp`.

## Правки модели до переноса (JS, шаг Б.0)

Делаются в `worlds/tenebrae/model.js` с тестами, веб на них не меняется; только потом копия в `tools/ref/`.

1. **Защиты:** `set(i, key, v)` — только `wave, cut, res, beat, fm, shift, amp`, иначе ничего; `grab`, `pin`, `remove`, `move`, `set`, `lfo` на неактивном голосе — ничего (`pin` возвращает `null`); `lfo(i, key, spec)` для нового ключа — `{ ...LFO_DEF, ...spec }`; поле `spec.ph` не пишется.
2. **Связи по номеру:** `mods[] = {src: <номер голоса>, type, depth, auto, k, until}`. `app.js` (мост, меню связи, кольцо, `dst.mods.includes(m)`) ищет связь по паре `(dst, src)` — хелпер модели `mod(dst, src)`; живых ссылок на объекты связей вид не хранит дольше кадра.

## Ядро

Файлы `core/worlds/tenebrae/model.hpp/.cpp` (модель, без звука), `world.hpp/.cpp` — как у Firmamentum: модель шлёт события слушателю (`listen`), мир превращает их в команды голосам (`voice`, `on`, `off`, `live`, `links`, `lfo`, `fx`, `strike`, `clear` — те же, что сейчас делает клей `engine.js`).

**Действия модели** (`enum Act` в `world.hpp`, новые коды от 16; коды 0–8 этапа 1 остаются как низкоуровневые — ими пользуются `test-tenebrae-core.mjs` и `render-cli`; вид их не шлёт):

| Код | Действие | Аргументы |
|---|---|---|
| SPAWN | `spawn` в заданный голос `i` | `[p, c, holeT]` — номер выбирает вызывающий (фасад / Swift) по тем же правилам, ядро не выбирает заново |
| GRAB, LETGO | пальцы | `LETGO [fade 0/1]` |
| KEEP, UNKEEP | плашка | `KEEP [i…]` |
| MOVE | место | `[p, c, holeT]` |
| SUN | глубина солнца | `[t]` |
| SET | поле | `[key, v]`, ключи — номерами в порядке списка выше |
| PIN, REMOVE, ATTACK, RELEASE | | `RELEASE [τ]` |
| LINK, LINKDEPTH, LINKTYPE, UNLINK | `i` = dst | `[src, depth, type]` / `[src, d]` / `[src, type]` / `[src]` |
| LFO | | `[key, morph, rate, depth]`, `depth < 0` — снять |
| FX | | `[rev, decay, dly, chaos, dirt]` |
| DICE, CLEAR, RETUNE | | |

Точные номера и раскладки — в комментарии `world.hpp` (как у Firmamentum), план их фиксирует.

**Время:** модель шагает в `process` раз в блок (`dt = n / sr`, `n ≤ 128`), как Firmamentum; тик хоста (`kind −1`) по-прежнему пропускается.

**Огибающая:** у модели своя `env / envT / envTau` (выбор жертвы, смерть голоса, `snap`) — как в эталоне; огибающая голоса (`Param ENV`) и шина `1/√Σenv` ядра не меняются.

**Случайность:** отдельный `sdk::Rng` модели от зерна `prepare` (своя константа XOR, не совпадает с шумом `0x54454e` и ударами).

**`heard`:** плоские записи `[1, i]` — `burst`, `[2, i, p]` — `strike` (то, что отдаёт `model.events()`).

**Снимок:** `snapshot()` — тот же JSON, что у `model.js` (символ в символ — сверка); `restore(js)` — тот же порядок. Лимит `STR_CAP` 64 КБ хватает.

**Зеркало:** `[заголовок: N голосов, time, strikes, fx×5, kept (число + номера)]`, на голос — поля модели (`active, live, pinned, held, x, y, beat, wave, fm, cut, res, shift, amp, holeT, sunT, env, envT`), связи (число + до 5 × `src, type, depth, auto`), LFO (8 ключей × `morph, rate, depth`, `depth 0` — нет), затем контур (как сейчас, 128 точек). Оценка ≈ 1 140 чисел. Пустое поле (нет активных) — короткое зеркало: заголовок и поля без контуров.

**Лимит зеркала 1024 → 2048** одновременно: `core/bridge/api.cpp` (`MBUF`), `core/app/engine.hpp` (`MIRROR_CAP`), `t2d-worklet.js` (`Float64Array(..., 1024)`), `core/bridge/t2d.h` (комментарий). На iOS зеркало длиннее `MIRROR_CAP` пропускается целиком — поэтому все четыре места в одном коммите.

## Веб

- `worlds/tenebrae/model.js` → **фасад** по образцу `worlds/firmamentum/model.js`: действие сразу правит `state` и уходит в ядро (`send`); зеркало ~60/с (`sync(mirror, applied)`) правит `state` по номерам голосов с правилами гонок Firmamentum (поля, которые фасад тронул и ядро ещё не применило, не перетираются). Только из зеркала: `env, envT, time, strikes`, авто-связи от хаоса, результат `dice`, смерть голосов в `tick`. `tick` фасада пустой. `events()` отдаёт записи `heard`.
- Синхронные ответы фасад считает сам по своему `state` той же логикой эталона: номер для `spawn` (жертва — по `env` из зеркала, отставание ≤ кадра), `pin` → `'pinned' / 'unpinned' / 'full'`, `dice()` → есть ли живые.
- `worlds/tenebrae/engine.js` — тонкий: `T.core.dry[1]` в канал, `bind` шлёт ядру всю сцену одним `restore`, `heard` → фасад. Память последних действий (`vo, lv, up, lk, lf, fxA`) уходит.
- `app.js`: перезапуск звука для Tenebrae — общий путь (`snapshot → build → restore`), особый случай `engine.bind` в `restartAudio` убирается. Отмена: шаг после `dice` и `clear` снимается, когда фасад получил зеркало с `applied` ≥ номера этого действия (иначе в историю уйдёт сцена до кубика).

## Решено без автора

1. Лимит зеркала поднимается до 2048, контуры не урезаются и не выносятся в отдельный канал — проще и картинка та же.
2. Огибающая модели остаётся своей (как в эталоне), огибающую голоса ядра не трогаем — точная сверка и тот же звук.
3. Номер голоса для `spawn` выбирает вызывающий; ядро не выбирает заново — фасад отвечает синхронно, ядро и фасад не расходятся.
4. Коды 0–8 этапа 1 остаются для сверки звука; вид шлёт только действия модели.
5. `dice` и хаос считает только ядро; фасад узнаёт результат из зеркала.
