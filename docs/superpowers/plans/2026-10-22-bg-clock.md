# Часы секвенсоров в фоне — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Portus, Natura и автострам Monochordum в фоне на iPhone играют все шаги: планировщик будит тик из AudioWorklet, а не только JS-таймер.

**Architecture:** `host/clock.js` — подписка `onTick(fn)`; подписчиков зовут постоянный `setInterval(25)` и сообщения процессора `'clock'` (`clock-worklet.js`, каждые 25 мс звукового времени). `build()` в `host/audio.js` поднимает метроном на каждом новом контексте. Engines трёх миров подписывают свои планировщики через `T.onTick`.

**Tech Stack:** ES-модули без сборки, Web Audio / AudioWorklet, Node `node --test`, Playwright (`tools/shot.py`).

**Spec:** `docs/superpowers/specs/2026-10-22-bg-clock-design.md`

## Global Constraints

- Ветка `fix/bg-clock`; в `main` — только после проверки автором на превью.
- Планировщики, запас 200 мс, звук — не меняются; меняется только то, что их зовёт.
- Таймер `setInterval(…, 25)` остаётся; тик worklet — вдобавок.
- Импорты `host/` — без `?v=`; версию для `addModule` даёт `app.js` (`setClockVer`).
- Ошибка `addModule` / узла метронома — без исключения наружу, остаётся таймер.
- `CACHE` в `sw.js` и все `?v=` в `index.html` — одно число, при выкладке: **167**.
- Комментарии — по-русски; коммиты — по-английски, тело-список, `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **`restartAudio`** — новый контекст: старый узел метронома отцеплен, новый поднят, тик не удваивается от старого (тест в Task 1).
2. **Метроном на `OfflineAudioContext`** (`tools/render.py`) — не должен ломать офлайн-рендер (проверка в Task 1: `render.py --onsets` проходит).
3. **Контекст ещё `suspended`** (до первого касания) — тиков от worklet нет, таймер работает как раньше (покрыто тем, что таймер не убираем; тест в Task 1 — подписчик зовётся таймером без worklet).
4. **Вход в мир до готовности метронома** — планировщик зовётся таймером, звук сразу (shot-сценарии в Task 2).
5. **Подписчик бросает исключение** — остальные подписчики всё равно вызываются (тест в Task 1).

**Interfaces:**
- Produces (`host/clock.js`): `onTick(fn: () => void): void`; `startClock(ctx: BaseAudioContext): void`; `setClockVer(v: string): void`; `clockLive(): boolean` (узел метронома текущего контекста поднят); `TICK_MS = 25`.
- Produces (`clock-worklet.js`): процессор `'clock'`, без входов, 1 выход (тишина), каждые `round(sampleRate * 0.025)` отсчётов — `port.postMessage(1)`.
- Produces (`window.T2D`): `onTick`, геттер `clockLive`.

- [ ] **Step 1: тест (падающий).** `tools/test-clock.mjs`, подделки: `globalThis.AudioWorkletNode` (запоминает созданные, `port.onmessage`, `connect`, `disconnect` — счётчик), `fakeCtx({ fail })` с `audioWorklet.addModule` (resolve / reject), `createGain` → `{ gain: { value }, connect }`, `destination`. Тесты:
  - `'a worklet message calls every subscriber'` — `onTick(a)`, `onTick(b)`, `startClock(ctx)`, дождаться, `node.port.onmessage({ data: 1 })` → `a` и `b` вызваны по разу; `clockLive()` — `true`;
  - `'a new context disconnects the old clock'` — `startClock(c1)`, `startClock(c2)` → узел `c1` `disconnect` вызван, сообщение от старого узла подписчиков не зовёт;
  - `'a failing addModule leaves the timer'` — `startClock(fakeCtx({ fail: true }))` не бросает; `clockLive()` — `false`; за 80 мс подписчик вызван таймером ≥ 2 раз;
  - `'a throwing subscriber does not stop the others'` — `onTick(() => { throw … })`, `onTick(b)`, сообщение → `b` вызван.
  Модуль импортировать один раз; между тестами состояние — через новые контексты (подписчики копятся — проверять счётчики на дельту).
